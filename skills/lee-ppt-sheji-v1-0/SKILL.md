# 可编辑 PPT 工作流核心规范

使用本技能时，目标始终是交付真正可编辑的 `.pptx`，而不是只交付页面图片。涉及图像生成、风格 Demo、无字底图生成或修复时调用 `imagegen` 技能。先读 [项目填写单](references/project-intake.md)，再按以下流程工作。

## 总原则

涉及重新设计排版、页面风格或整套视觉时，必须遵循：

**先图文一体设计，后拆层交付。**

无字底图是最终交付拆层结果，不是设计起点。不得先生成无字底图再后期硬贴文案。

所有不确定、缺失或会影响结果的信息，必须优先向用户提问确认，不得猜测答案；只有用户明确允许 AI 推荐或默认处理时，才可给出推荐并标注为假设。

## 强制阶段门禁

涉及新建、重排、重做或大幅改版 PPT 时，必须按阶段推进。每一步完成后都必须暂停，等待用户明确确认，禁止提前进入下一步。

只要用户要求“设计 / 重做 / 制作 / 优化 / 重新梳理 PPT”，默认从阶段 1 开始执行，不得直接生成最终 PPTX。只有用户明确说“跳过流程，直接生成最终 PPT”或同等含义时，才允许跳过阶段门禁。

在阶段 1-7 全部完成并得到对应确认前，禁止生成最终 PPTX。阶段 3 风格 Demo、阶段 5 整套带文案图片预览、阶段 6 无字底图确认，是最终 PPTX 前的强制门禁，不得省略或合并为最终制作。

如果用户说明“我要一页一页确认”“逐页确认”“每页确认后再继续”或同等含义，则进入逐页确认模式：每一页的内容、真实文案、版式、主视觉和文字区域都必须先给用户确认；用户确认当前页后，才可进入下一页或最终 PPTX 制作。

## 确认交互规则

- 阶段 1 末尾必须只提示一次：`后续回复 0 表示确认、接受 AI 建议或进入下一步。` 后续每个阶段、每个问题不得重复解释 `0` 的含义，直接按该约定识别并跳转下一步。
- 用户确认某一阶段后，只需用一句话简短归纳已确认信息，并直接进入下一阶段的提问或产出；不得再次要求用户二次确认同一内容。
- 当用户指出修改意见时，按当前阶段做定向修改，完成后回到该阶段确认点，不倒退重复询问已确认的信息。

## 固定顺序

1. **核心内容或附件确认**
   核心内容或附件为必填。必须先确认输入来源：文案、旧 PPT、截图、PDF、图片素材、品牌资料或其他内容源。

2. **基础信息整合确认**
   本阶段不再默认逐题询问。完成阶段 1 的核心内容或附件确认后，先从用户提供的资料中自动读取和分析基础信息，再一次性输出“阶段 2：综合确认结果”。只有资料不足、冲突严重或用户明确要求逐项确认时，才启用原 9 题兜底模式。

   自动读取范围包括：文档标题、正文标题、摘要、目录、章节结构；旧 PPT 的封面、页脚、母版、配色、字体、页面比例、页数；PDF、截图、图片中的文字、logo、品牌色、画面比例；用户在对话中已经说明的目标、受众、风格、页数、限制条件；文件名、文件夹名、附件名称中的主题和场景线索。

   每个识别结果后必须标注可信度：高、中、低、AI 规划、未识别。高表示资料中有明确文字、标题、logo、尺寸、页数或用户原话支持；中表示资料中多处出现相关线索，可以合理推断；低表示仅能根据内容类型、语气或结构弱推断；AI 规划表示资料中没有明确答案，由 AI 基于需求文件给出建议；未识别表示资料中没有足够线索且不适合 AI 直接规划。不得把低可信推断或 AI 规划包装成资料中的确定结论。可信度展示时，高、中、低分别使用黄色星标 `<span style="color:#F5B301">★★★</span>`、`<span style="color:#F5B301">★★</span>`、`<span style="color:#F5B301">★</span>`；AI 规划和未识别直接写文字描述。

   页面比例默认写死为 `16:9`。阶段 2 不主动提供其他比例选项，也不提示用户可修改。除非用户主动明确提出其他比例，否则始终按 `16:9` 执行。

   品牌色必须优先执行关键词识别。只要参考资料、文件名、正文、截图 OCR、旧 PPT 文本或用户对话中任意位置出现“普乐师、Plus、flux、fluxPlus、FluxMens、即时零售、数字化动销、动销场景、动销”任一字样，必须首先推荐品牌色 `#0E76C3`。如果没有命中关键词，但资料中存在明确品牌色，则采用资料中的品牌色并标注依据。如果既没有命中关键词，也没有明确品牌色，AI 必须根据需求文件的行业属性、内容气质、受众和使用场景给出一套主色方案，标注为“AI 规划”。

   字体不再开放泛化选择，固定提供 3 套默认可选方案：Mac 系统默认字体方案、Win 系统默认字体方案、微软雅黑托底方案。阶段 2 需要先从用户对话、文件来源、编辑环境描述中判断使用终端。用户明确说明使用 Mac 或 Windows 时，直接推荐对应系统默认字体方案；用户未说明终端、需要多人协作、客户交付或跨终端编辑时，默认推荐微软雅黑托底方案，并提示使用者提前安装或确认环境支持，以减少跨设备错位和字体授权风险。

   字体方案必须写清楚标题、正文、英文、大数字四类文本标准：Mac 系统默认字体方案为标题 PingFang SC Semibold、正文 PingFang SC Regular、英文 SF Pro Display / SF Pro Text、大数字 SF Pro Display Semibold；Win 系统默认字体方案为标题 Microsoft YaHei UI Semibold、正文 Microsoft YaHei UI Regular、英文 Segoe UI、大数字 Segoe UI Semibold；微软雅黑托底方案为标题 Microsoft YaHei Bold、正文 Microsoft YaHei Regular、英文 Arial、大数字 Arial Bold。

   阶段 2 综合确认结果必须使用有序列表，方便用户按序号提出修改意见。每一项必须使用三行结构：第一行写序号、字段名和加粗结果；第二行单独写可信度；第三行单独写依据。不得把结果、可信度、依据挤在同一行。顺序固定为：任务类型、主题与一句话目标、目标场景、主要受众、页面比例、品牌色、logo、IP 形象、字体、正文页数、封面/封底。“更多要求”不再作为固定字段输出；用户如已主动提出额外要求，则合并进对应字段或在确认表末尾增加“特殊要求”。

   阶段 2 输出综合确认表后，只用一句话追问：`是否下一步？` 不得重复解释 `0` 的含义。用户若需要修改，可直接按确认表序号提出修改意见，例如“改第 6 条为黑金风格”或“第 10 条改成 6 页”。页面比例不进入追问项，默认始终执行 `16:9`。

3. **风格偏好与关键页 Demo 可视化确认**
   在生成 4 个风格方向之前，必须先基于已确认的内容、页数、目标场景、受众、品牌要求和页面比例，给出一张“推荐选择表”，用于锁定内容组织方式。该表不作为额外复杂确认轮次，用户可回复 `0` 采纳 AI 推荐，也可指定修改其中任一项。

   推荐选择表必须至少包含：场景、叙事结构、信息密度、推荐视觉。确认后，再根据该内容组织方式推荐 4 个适配风格方向。

   每个风格方向必须用 Image 2 / imagegen 生成一组带真实文案的关键页高质量 Demo，而不是只生成抽象风格板。默认每个风格方向各生成 2 张独立 Demo 图片：封面页 + 元素拆解页，并按风格分组展示在对应风格说明下方；不得用一张四宫格风格板代替 4 组关键页 Demo。

   如果用户上传素材并明确指定为风格参考，必须把该素材风格插入 4 个可选风格中作为备选，并标注来源。

   风格 Demo 是用户选型的重要依据；用户选择某个风格后，默认表示对该组 Demo 的核心页面样式满意。后续整套图片排版预览应尽量直接沿用被选中 Demo 的版式语言、色彩、质感和页面样式，不得无故重新生成另一个风格。

4. **主风格锁定**
   用户选择主风格后，记录风格契约。若融合辅助风格，必须明确主次关系。锁定风格时同步锁定被选中 Demo 的可复用页面样式，包括标题位置、视觉主轴、卡片质感、留白节奏、图文关系和品牌色使用方式。

5. **整套图片排版预览**
   用户确认主风格后，基于已选 Demo 样式生成全稿带真实文案的图片预览。可以提供多页合成一页的缩略图 / contact sheet 供快速浏览，但必须同时保存每个页面的单张高清图到独立过程文件夹，保证可追溯。

   这里的“排版预览图片”特指 Image 2 / imagegen 生成的带真实文案设计稿，用于确认图文融合、页面构图和视觉风格；不是最终 PPTX 映射可编辑文字后的导出截图。

6. **无字底图拆层**
   用户确认带文案预览后，才生成或整理无字底图版，用于最终 PPTX 底层。无字底图 PNG 必须逐页保存到独立文件夹。

7. **可编辑 PPTX 制作**
   用“无字视觉底图 + 原生可编辑文字/数字/标签”结构制作 PPTX，并复刻确认稿中的文字位置、层级、字号和对齐关系。

   推荐有效产出链路：确认无字底图通过 → 一次生成 PPTX → 轻量结构检查 → 必要时用 PowerPoint 后台导出 PNG 看总览 → 小修 → 最终导出。PowerPoint 导出 PNG 只是 QA 手段，不属于阶段 5 的正式排版预览交付物；如果导出失败或工具异常，最多尝试一次替代方案，不得反复排查拖慢交付。

## 禁止事项

- 不得因用户说“生成 PPT / 制作 PPT / 设计 PPT”就直接进入最终 PPTX 制作；默认必须先走阶段 1。
- 未完成阶段 1-7 的逐步确认前，不得生成最终 PPTX。
- 用户要求逐页确认时，不得跳过单页确认直接生成整套最终 PPTX。
- 阶段 2 不得在资料可分析时默认进入 9 题逐项询问；必须先自动读取资料并输出有序列表版“阶段 2：综合确认结果”。
- 阶段 2 综合确认结果不得使用无序项目符号；必须使用有序列表，字段顺序固定为：任务类型、主题与一句话目标、目标场景、主要受众、页面比例、品牌色、logo、IP 形象、字体、正文页数、封面/封底。
- 阶段 2 综合确认结果不得把结果、可信度和依据挤在同一行；每项必须三行展示，结果必须加粗，可信度和依据必须换行书写。
- 阶段 2 不得把“更多要求”作为固定字段输出；用户主动提出额外要求时，才合并进对应字段或追加“特殊要求”。
- 阶段 2 不得主动提示页面比例可修改；除非用户主动明确提出其他比例，否则始终按 `16:9` 执行。
- 阶段 2 不得重复解释 `0` 的含义；综合确认表后只问“是否下一步？”。
- 阶段 2 不得忽略品牌关键词；资料中出现“普乐师、Plus、flux、fluxPlus、FluxMens、即时零售、数字化动销、动销场景、动销”任一字样时，必须首先推荐 `#0E76C3`。
- 阶段 2 不得使用来源不明或有侵权风险的商用字体作为默认方案；字体只能在 Mac 系统默认字体方案、Win 系统默认字体方案、微软雅黑托底方案中选择，并写清标题、正文、英文、大数字四类文本标准。
- 未确认核心内容或附件，不得规划页数。
- 未确认阶段 3 的风格与关键页 Demo，不得生成整套图片预览或 PPTX。
- 未确认带文案整套图片预览，不得制作可编辑 PPTX。
- 不得用脚本拼接的低保真草图冒充 Image 2 高质量风格 Demo 或关键页 Demo。
- 不得只用文字说明让用户定风格。
- 不得把风格 Demo 图直接铺成每页背景；风格 Demo 只用于提取视觉语言，每页需按内容重新设计。
- 不得先生成无字底图再后期贴文案来替代设计稿确认。
- 若图文割裂，不得硬移文字适配底图，应优先重生成对应页面设计稿或底图。

除阶段 2 的综合确认外，每次回复开头必须声明当前阶段，例如：“阶段 3：风格偏好与关键页 Demo 可视化确认”。阶段 2 必须使用标题“阶段 2：综合确认结果”，并在确认表后只问“是否下一步？”。

## 图文一体设计要求

进入关键页 Demo 或整套图片预览前，必须先锁定真实文案，包括每页标题、正文、要点数量和文字长短。

Image 2 / imagegen 提示词必须明确：页面真实标题和正文、要点数量、文字区域位置、文字密度、留白要求、角色/主视觉与文字的关系，并禁止生成乱码、伪文字、无关文字或水印。

关键页 Demo 和整套图片预览必须优先生成带真实文案版。只有在用户确认带文案设计稿后，才可拆出或重绘无字底图。

## 预览与验证边界

- 阶段 5 必须保存的是带真实文案的 Image 设计稿：逐页高清图 + 缩略总览，用于用户确认和过程追溯。
- 阶段 6 必须保存的是无字底图 PNG：逐页高清图，用于最终 PPTX 底层。
- 阶段 7 的 PPTX 导出截图只是质量检查，不是正式排版预览交付物。
- 阶段 7 必须做轻量结构检查：页数、底图数量、可编辑文本层、中文写入、关键替换词和文件是否存在。
- 只有在怀疑文字错位、遮挡、溢出，或用户明确要求视觉核对时，才导出 PPTX 渲染图 / PNG 总览检查。

## 分辨率与字号映射

当参考设计稿、截图、图片或 PDF 页面分辨率不固定，且需要拆成 PPT 页面时：

1. 必须记录参考图原始宽高和目标 PPT 页面宽高。
2. 建立归一化坐标：`x / y / w / h` 均按原始宽高比例换算。
3. 字号必须按原始图中文字高度、行距和页面比例推导。
4. 映射到 PPT 后，所有字号必须向上取整为整数 pt。
5. 不得为了塞文字而自动缩小字号；应优先改文案、改版式或重生成底图。
6. 同一文本角色，如标题、正文、标签、注释、页码，必须使用统一字号体系。

## 路径选择

| 输入与目标 | 路径 |
| --- | --- |
| 文案、文档或主题 → 新 PPT | A：图文一体设计到可编辑 PPT |
| 旧 PPT / 截图 / PNG / PDF → 高保真复刻 | B：视觉重建 |
| 旧 PPT 内容 + 新视觉重排 | C：内容重组 + 图文一体重设计 |

路径 A/C 必须先带文案设计，再拆无字底图。路径 B 可从参考图移除文字重建底图，但仍必须人工核对文字、位置、字号和图层。

## 交付

始终交付可编辑 PPTX；新建或编辑内容时保留原文件，另导出新版本。

交付物和过程文件应至少包含：

```text
delivery/                                  # 最终交付与过程文件总目录
├── <topic>-editable.pptx                  # 最终可编辑 PPTX，文字/数字/标签应为原生可编辑层
├── backgrounds-no-text/                   # 无字底图目录，用于 PPTX 底层视觉
│   ├── slide-01-background.png            # 第 1 页无字底图，不应包含文字、数字、页码或 logo 文案
│   └── ...
├── preview-pages/                         # 带真实文案的 Image 设计稿单页预览目录
│   ├── slide-01-preview.png               # 第 1 页带文案设计稿，用于用户确认图文融合与版式
│   └── ...
├── preview-contact-sheet.png              # 多页缩略总览，用于快速查看整套预览节奏
├── source-or-reference/                   # 原始 PPT、参考图、品牌素材、IP 素材等来源文件
└── manifest.json                          # 拆层映射说明；路径 B 或复杂拆层时必需
```

最终说明只报告：产物位置、页数、采用的风格 / 关键假设、已完成的验证、主要过程文件夹位置。不要把草稿计划、临时图、内部提示词或未确认预览当成正式交付。
