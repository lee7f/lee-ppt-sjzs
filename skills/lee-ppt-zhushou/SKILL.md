# 可编辑 PPT 工作流 V1.1 核心规范

使用本技能时，目标始终是交付真正可编辑的 `.pptx`，而不是只交付页面图片。涉及图像生成、风格 Demo、整套 image 设计稿、底图插画生成或修复时调用 `imagegen` 技能。先读 [项目填写单](references/project-intake.md)，再按以下流程工作。

## 总原则

涉及重新设计排版、页面风格或整套视觉时，必须遵循：

**先图文一体设计，后拆层交付。**

image 设计稿是设计确认依据；拆层素材是最终交付结构，不是设计起点。不得先生成无字底图再后期硬贴文案。

所有不确定、缺失或会影响结果的信息，优先从用户资料中读取；资料不足、冲突严重或边界不明时再向用户提问。AI 给出的补全必须标注为“AI 规划”，不得包装成资料中的确定结论。

## 文本与版式硬规范

- 所有 PPT 原生文字行高统一为 `1.2`。
- 文本框默认跟随文字大小，不固定成多余大框。
- 文本框内边距统一为 `0`，包括左、右、上、下内边距。
- 相同层级的文字必须使用相同字体、字号、字重、颜色和行高。
- 设计稿中的页码可以作为整体设计元素处理，不限于单纯数字提示。
- 封面和封底不计入页码编号；正文第一页从 `01` 或 `1` 开始，需与整体风格一致。
- 带文案 image 设计稿必须带页码；无字底图不得包含文字、数字、页码或 logo 文案；最终 PPTX 页码使用 PPT 原生文本层或母版元素实现。

## 强制阶段门禁

涉及新建、重排、重做或大幅改版 PPT 时，必须按阶段推进。每一步完成后都必须暂停，等待用户明确确认，禁止提前进入下一步。

只要用户要求“设计 / 重做 / 制作 / 优化 / 重新梳理 PPT”，默认从阶段 1 开始执行，不得直接生成最终 PPTX。只有用户明确说“跳过流程，直接生成最终 PPT”或同等含义时，才允许跳过阶段门禁。

阶段 3 风格 Demo、融合风格 Demo（仅当用户选择融合风格时）、阶段 4 整套带文案 image 设计稿、阶段 5 拆层维度确认与素材确认，是最终 PPTX 前的强制门禁，不得省略或合并为最终制作。

如果用户说明“我要一页一页确认”“逐页确认”“每页确认后再继续”或同等含义，则进入逐页确认模式：每一页的内容、真实文案、版式、主视觉和文字区域都必须先给用户确认；用户确认当前页后，才可进入下一页或最终 PPTX 制作。

## 确认交互规则

- 阶段 1 末尾必须只提示一次：`后续回复 0 表示确认、接受 AI 建议或进入下一步。` 后续每个阶段、每个问题不得重复解释 `0` 的含义，直接按该约定识别并跳转下一步。
- 用户确认某一阶段后，只需用一句话简短归纳已确认信息，并直接进入下一阶段的提问或产出；不得再次要求用户二次确认同一内容。
- 当用户指出修改意见时，按当前阶段做定向修改，完成后回到该阶段确认点，不倒退重复询问已确认的信息。

## 固定流程

### 阶段 1：核心资料确认与需求分型

核心内容或附件为必填。必须先确认输入来源：文案、旧 PPT、截图、PDF、图片素材、品牌资料或其他内容源。

根据资料状态判断需求类型，并按类型决定提问深度：

1. **引导式**：用户没有提供可分析资料，或只是调用 Skill。AI 需要用最少问题引导用户补齐主题、目标、场景、受众和基础产出要求。
2. **资料解析式**：用户提供了相对丰富且完整的资料。AI 先自动分析资料，给出识别结果、可信度和依据，再让用户确认或修改。
3. **视觉优化型**：用户上传 PPT 骨架文件，目标是视觉优化。必须确认优化边界：文字是否可改、页面结构是否可重搭、页数和内容是否可重排、密集页是否可拆成多页、原贴图是否必须完整保留。

未确认核心内容或附件前，不得规划页数。

### 阶段 2：综合信息梳理确认

本阶段不默认逐题询问。完成阶段 1 后，先从用户提供的资料中自动读取和分析基础信息，再一次性输出“阶段 2：综合确认结果”。只有资料不足、冲突严重或用户明确要求逐项确认时，才启用兜底提问。

自动读取范围包括：使用者身份、受众、使用场景、演讲时长、主题、作者、联系方式、企业品牌信息、品牌色、logo、IP 形象、字体、页面比例、页面数量、是否需要封面和封底、文档标题、正文标题、摘要、目录、章节结构、旧 PPT 的封面、页脚、母版、配色、字体、页面比例和页数。

每个识别结果后必须标注可信度：高、中、低、AI 规划、未识别。高表示资料中有明确文字、标题、logo、尺寸、页数或用户原话支持；中表示资料中多处出现相关线索，可以合理推断；低表示仅能根据内容类型、语气或结构弱推断；AI 规划表示资料中没有明确答案，由 AI 基于需求文件给出建议；未识别表示资料中没有足够线索且不适合 AI 直接规划。

页面比例默认写死为 `16:9`。阶段 2 不主动提供其他比例选项，也不提示用户可修改。除非用户主动明确提出其他比例，否则始终按 `16:9` 执行。

品牌色必须优先执行关键词识别。只要参考资料、文件名、正文、截图 OCR、旧 PPT 文本或用户对话中任意位置出现“普乐师、Plus、flux、fluxPlus、FluxMens、即时零售、数字化动销、动销场景、动销”任一字样，必须首先推荐品牌色 `#0E76C3`。如果没有命中关键词，但资料中存在明确品牌色，则采用资料中的品牌色并标注依据。如果既没有命中关键词，也没有明确品牌色，AI 必须根据需求文件的行业属性、内容气质、受众和使用场景给出一套主色方案，标注为“AI 规划”。

字体不开放泛化选择，固定在 3 套默认可选方案中选择：Mac 系统默认字体方案、Win 系统默认字体方案、微软雅黑托底方案。字体方案必须写清标题、正文、英文、大数字四类文本标准。

阶段 2 综合确认结果必须使用有序列表。每一项使用三行结构：第一行写序号、字段名和加粗结果；第二行单独写可信度；第三行单独写依据。顺序固定为：任务类型、需求类型、主题与一句话目标、目标场景、使用者身份、主要受众、演讲时长、页面比例、品牌色、logo、IP 形象、字体、正文页数、封面/封底、作者/联系方式。用户如已主动提出额外要求，则合并进对应字段或在确认表末尾增加“特殊要求”。

阶段 2 输出综合确认表后，只用一句话追问：`是否下一步？` 不得重复解释 `0` 的含义。

### 阶段 3：风格建议与关键页 Demo 确认

收集到足够信息后，AI 必须一次性推荐 4 个相对适配的风格方向，并在给出建议的同时生成风格 Demo。不得先只给风格名称或文字描述让用户判断，再等待确认后才生成 Demo。

每个风格方向必须使用 Image 2 / imagegen 生成一组带真实文案的关键页高质量 Demo。默认每个风格方向各生成 2 张独立 Demo 图片：封面页 + 内页，不得用一张四宫格风格板代替 4 组关键页 Demo。

风格推荐说明应包括：适用场景、叙事结构、信息密度、推荐视觉、适合原因。用户可选择单一风格，也可选择多风格融合；风格融合时必须明确主风格和辅助风格的主次关系。

如果用户选择多风格融合，必须先生成一版“融合风格 Demo”供确认，至少包含封面 + 内页。融合 Demo 必须写清主风格、辅助风格、融合比例、保留元素和弱化元素。用户确认融合 Demo 后，才能进入阶段 4。

如果用户上传素材并明确指定为风格参考，必须把该素材风格插入 4 个可选风格中作为备选，并标注来源。

用户选择单一风格后，默认表示对该组 Demo 的核心页面样式满意；用户确认融合风格 Demo 后，默认表示对融合后的核心页面样式满意。后续整套 image 设计稿应尽量沿用被确认 Demo 的版式语言、色彩、质感和页面样式，不得无故重新生成另一个风格。

### 阶段 4：整套 image 设计稿生成

用户确认风格后，先询问用户选择输出方式：一次性输出全部设计稿，或按 4 页一组分批输出。

- 一次性输出：生成全部带真实文案的 image 设计稿，并提供缩略总览。
- 分批输出：每组默认 4 页，用户确认当前组后再生成下一组，直至全部完成。

每页 image 设计稿必须包含真实标题、正文、要点、页码和设计元素，用于确认图文融合、页面构图和视觉风格。设计稿必须带页码；封面和封底不计入页码编号。

如果页面内容或正文页数由 AI 规划，必须同步保存一份 `page-plan.md` 存档，记录项目标题、需求类型、正文页数（不含封面/封底）、每页编号、页面标题、核心内容、建议视觉、AI 规划依据和关键假设。用户后续确认或修改页纲时，应更新该文件。

所有单页高清设计稿保存到 `preview-pages/`，文件名前必须加入页码编号，例如 `01-title-preview.png`。不得再按页创建子文件夹。

### 阶段 5：设计稿拆层与素材整理

用户确认带文案 image 设计稿后，进入拆 PPT 前必须先询问操作人拆层维度，不得直接按增强拆层执行。询问时必须写清默认维度，并把可选拆层维度作为编号选项列出。

默认拆层维度为：

- 底图层：整页无字背景 PNG。
- 文字层：PPT 原生可编辑文字，行高 `1.2`，文本框跟随文字大小，内边距为 `0`。

可选拆层维度为：

1. 插画层：独立 PNG，只输出 PNG，不输出 SVG。
2. 图标层：独立 SVG，只输出 SVG，不输出 PNG。
3. 标签框 / 输入框 / 卡片样式：PPT 原生形状。

询问文案必须支持以下输入规则：用户输入 `0` 表示按默认拆层维度执行；用户输入 `1`、`2`、`3` 或组合编号（如 `12`、`13`、`23`）表示在默认维度基础上增加对应层级；用户输入 `123` 表示 3 个可选层级全部增加，此时不再需要整页底图层，最终按“插画 PNG + 图标 SVG + 原生文字 + 原生形状”拆层。

只要用户未选择 `123`，就必须保留整页无字底图层。只有用户明确选择 `1` 时才创建 `illustrations-png/`；只有用户明确选择 `2` 时才创建 `icons-svg/`；只有用户明确选择 `3` 时才把标签框、输入框和卡片样式拆为 PPT 原生形状。

素材文件夹不按页分子文件夹：

```text
backgrounds-no-text/                       # 默认底图层，整页无字背景 PNG
├── 01-background.png
├── 02-background.png
└── ...
illustrations-png/                         # 可选插画层，选择 1 或 123 时创建
├── 01-main-illustration.png
├── 02-process-illustration.png
└── ...
icons-svg/                                 # 可选图标层，选择 2 或 123 时创建
├── 01-arrow-icon.svg
├── 02-data-icon.svg
└── ...
```

所有素材文件名前必须加入对应页码编号，便于追溯到设计稿页面。

### 阶段 6：可编辑 PPTX 制作与验收

按阶段 5 已确认的拆层维度制作 PPTX。默认结构为“整页无字底图 PNG + 原生可编辑文字”；如用户选择可选层级，则在默认结构基础上增加对应的插画 PNG、图标 SVG 或原生形状；如用户选择 `123`，则不使用整页底图层，改用“插画 PNG + 图标 SVG + 原生可编辑文字 + 原生形状”结构。制作时必须复刻确认稿中的文字位置、层级、字号、行高和对齐关系。

最终 PPTX 必须执行验收检查：

1. PPTX 文件存在且可打开。
2. 页数与确认页数一致，封面和封底不计入正文页码编号。
3. 拆层维度与阶段 5 的用户选择一致；未选择 `123` 时存在整页无字底图层，选择 `123` 时不强制生成整页底图层。
4. 如选择插画层，插画 PNG 已独立存放，且文件名前有页码编号。
5. 如选择图标层，图标只输出 SVG，不混入 PNG 图标，且文件名前有页码编号。
6. 文字、数字、标签、页码为 PPT 原生可编辑文本。
7. 所有原生文字行高为 `1.2`，文本框跟随文字大小，内边距为 `0`。
8. 如选择标签框 / 输入框 / 卡片样式层，对应元素为 PPT 原生形状。
9. 相同层级文字的字体、字号、字重、颜色和行高一致。
10. 各层元素的大小、位置与确认设计稿基本一致。
11. 中文无乱码，关键标题、品牌名、页码和替换词正确。
12. 若页面内容或数量由 AI 规划，`page-plan.md` 已存在且内容与最终页数一致。
13. 过程文件目录完整。

如怀疑文字错位、遮挡、溢出，或用户明确要求视觉核对，才导出 PPTX 渲染图 / PNG 总览检查。PowerPoint 导出 PNG 只是 QA 手段，不属于阶段 4 的正式 image 设计稿交付物。

## 禁止事项

- 不得因用户说“生成 PPT / 制作 PPT / 设计 PPT”就直接进入最终 PPTX 制作。
- 未确认核心内容或附件，不得规划页数。
- 未确认阶段 3 的风格与关键页 Demo，不得生成整套 image 设计稿或 PPTX。
- 未确认带文案整套 image 设计稿，不得制作可编辑 PPTX。
- 未询问并确认拆层维度，不得拆层或制作可编辑 PPTX。
- 不得用脚本拼接的低保真草图冒充 Image 2 高质量风格 Demo 或关键页 Demo。
- 不得只用文字说明让用户定风格。
- 不得把风格 Demo 图直接铺成每页背景；风格 Demo 只用于提取视觉语言，每页需按内容重新设计。
- 不得先生成无字底图再后期贴文案来替代设计稿确认。
- 不得把图标导出为 PNG；图标源文件统一为 SVG。
- 不得把插画导出为 SVG；插画统一为 PNG。
- 不得按页创建素材子文件夹；默认底图、可选插画和可选图标分别使用 `backgrounds-no-text/`、`illustrations-png/`、`icons-svg/`，并按用户确认的拆层维度创建。

除阶段 2 的综合确认外，每次回复开头必须声明当前阶段，例如：“阶段 3：风格建议与关键页 Demo 确认”。阶段 2 必须使用标题“阶段 2：综合确认结果”，并在确认表后只问“是否下一步？”。

## 交付

始终交付可编辑 PPTX；新建或编辑内容时保留原文件，另导出新版本。

交付物和过程文件应至少包含：

```text
delivery/
├── <topic>-editable.pptx                  # 最终可编辑 PPTX
├── preview-pages/                         # 带真实文案和页码的 image 设计稿
│   ├── 01-cover-preview.png
│   ├── 01-content-preview.png
│   └── ...
├── preview-contact-sheet.png              # 多页缩略总览
├── page-plan.md                           # AI 规划页面内容或数量时必需
├── backgrounds-no-text/                   # 默认底图层；选择 123 全拆层时可不生成
│   ├── 01-background.png
│   └── ...
├── illustrations-png/                     # 可选插画层；选择 1 或 123 时创建
│   ├── 01-main-illustration.png
│   └── ...
├── icons-svg/                             # 可选图标层；选择 2 或 123 时创建
│   ├── 01-data-icon.svg
│   └── ...
├── source-or-reference/                   # 原始 PPT、参考图、品牌素材、IP 素材等来源文件
└── manifest.json                          # 拆层映射说明
```

最终说明只报告：产物位置、页数、采用的风格 / 关键假设、已完成的验证、主要过程文件夹位置。不要把草稿计划、临时图、内部提示词或未确认预览当成正式交付。
