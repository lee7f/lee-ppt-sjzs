# 可编辑 PPT 工作流核心规范

使用本技能时，目标始终是交付真正可编辑的 `.pptx`，而不是只交付页面图片。始终先调用 `presentations` 技能；涉及图像生成、风格 Demo、无字底图生成或修复时调用 `imagegen` 技能。先读 [项目填写单](references/project-intake.md)，再按以下流程工作。

## 总原则

涉及重新设计排版、页面风格或整套视觉时，必须遵循：

**先图文一体设计，后拆层交付。**

无字底图是最终交付拆层结果，不是设计起点。不得先生成无字底图再后期硬贴文案。

所有不确定、缺失或会影响结果的信息，必须优先向用户提问确认，不得猜测答案；只有用户明确允许 AI 推荐或默认处理时，才可给出推荐并标注为假设。

## 强制阶段门禁

涉及新建、重排、重做或大幅改版 PPT 时，必须按阶段推进。每一步完成后都必须暂停，等待用户明确确认，禁止提前进入下一步。

## 确认交互规则

- 前几次给用户选择时，需要说明 `0` 表示“采纳 AI 推荐 / 确认进入下一步”。用户已经连续使用 `0` 形成习惯后，后续可直接把 `0` 识别为确认或采纳推荐，不必每次重复解释。
- 用户确认某一阶段后，只需用一句话简短归纳已确认信息，并直接进入下一阶段的提问或产出；不得再次要求用户二次确认同一内容。
- 当用户指出修改意见时，按当前阶段做定向修改，完成后回到该阶段确认点，不倒退重复询问已确认的信息。

固定顺序：

1. **核心内容或附件确认**  
   核心内容或附件为必填。必须先确认输入来源：文案、旧 PPT、截图、PDF、图片素材、品牌资料或其他内容源。

2. **基础信息整合确认**  
   本阶段整合原先分散的页数、目标场景、受众、品牌要求和页面比例确认，但必须保持“一个问题一问一答”的向导式体验：每次只问一个问题，等待用户回答后再问下一个问题。允许用户直接回复编号、组合编号、简短文字或 `0` 快速采纳当前 AI 推荐 / 默认值。  
   本阶段内部问题必须按以下顺序推进：目标场景 → 受众 → 品牌要求 → 页面比例 → 内容页数。不得一次性把所有问题全部抛给用户。  
   2.1 目标场景：必须编号罗列常用选项，可单选或多选：1. 汇报；2. 路演；3. 培训；4. 方案提案；5. 复盘。默认由 AI 结合内容推荐；不设置“自定义”选项，用户如有不同场景会直接写明，必须照常识别和记录。  
   2.2 受众：必须编号罗列常用选项，可单选或多选：1. 老板；2. 客户；3. 团队；4. 投资人；5. 学员。默认由 AI 结合内容推荐；不设置“自定义”选项，用户如有不同受众会直接写明，必须照常识别和记录。  
   2.3 品牌要求：采用问答式确认，不给固定备选项。默认保留或启用已知品牌色；当用户提到“普乐师蓝”“企业标准色”“品牌标准蓝”等指向普乐师企业标准色的词语时，默认识别为 `#0E76C3`。必须提示用户可上传 logo、IP 形象、品牌素材或说明沿用原 PPT 中的品牌信息；如存在多个 logo / IP / 品牌素材，必须确认主次关系和使用优先级。其他品牌限制用户未提供时，不强行限制，记录为“未提供 / 无明确限制”。  
   2.4 页面比例：默认 16:9，只需请用户确认；如果有不同页面比例需求，让用户直接写明，不额外提供备选比例。若已有设计稿、截图或参考图分辨率不固定，必须记录原始分辨率，并映射到目标 PPT 页面比例。字体、边距、坐标和字号比例必须根据当前分辨率换算，所有字号计算结果必须向上取整为整数 pt。  
   2.5 内容页数：只确认正文页数，不包含封面和封底。默认由 AI 根据内容密度、目标场景、受众和演讲时长推荐；可以询问用户是否有预计演讲时长用于换算页数。不得设置“用户指定 / 自定义页数”选项；用户如果直接写页数，必须识别为用户需求并记录。封面和封底另计。  
   以上 5 个问题全部回答完后，必须输出一份“阶段 2 综合确认结果”，完整列出目标场景、受众、品牌要求、页面比例、正文页数及封面封底是否另计，并等待用户确认后再进入下一阶段。

3. **风格偏好与关键页 Demo 可视化确认**  
   在生成 4 个风格方向之前，必须先基于已确认的内容、页数、目标场景、受众、品牌要求和页面比例，给出一张“推荐选择表”，用于先锁定内容组织方式。该表不作为额外复杂确认轮次，而是阶段 3 的前置判断，用户可回复 `0` 采纳 AI 推荐，也可指定修改其中任一项。  
   推荐选择表必须至少包含：场景、叙事结构、信息密度、推荐视觉。可参考以下结构：
   - 项目复盘：背景 → 目标 → 过程 → 结果 → 复盘 → 行动；信息密度中；推荐视觉为关键数据 + 过程证据。
   - 方案/提案：问题 → 洞察 → 方案 → 价值 → 路线 → 请求；信息密度低至中；推荐视觉为强主视觉 + 少量框架。
   - 知识分享：钩子 → 概念 → 方法 → 案例 → 总结；信息密度中；推荐视觉为图解或单一隐喻。
   - 个人表达：钩子 → 立场 → 故事 → 转折 → 收束；信息密度低；推荐视觉为编辑感照片或抽象材质。
   如果当前任务不属于上述场景，必须根据实际内容新增更贴合的推荐项，不得生搬硬套表格示例。  
   推荐选择表确认后，再根据该内容组织方式推荐 4 个适配风格方向。可包含但不限于：高级简洁、咨询报告、科技感、品牌发布、小红书感、杂志感、自定义。  
   每个风格方向必须用 Image 2 / imagegen 生成一组带真实文案的关键页高质量 Demo，而不是只生成抽象风格板。默认每个风格方向各生成 2 张独立 Demo 图片：封面页 + 元素拆解页，并按风格分组展示在对应风格说明下方；不得用一张四宫格风格板代替 4 组关键页 Demo。  
   如成本或时间需要控制，至少每个风格生成 1 张最能代表该风格的关键页 Demo，并明确说明这是降级方案，等待用户确认后才能执行。  
   如果用户上传素材并明确指定为风格参考，必须把该素材风格插入 4 个可选风格中作为备选，并标注来源。  
   风格 Demo 是用户选型的重要依据；用户选择某个风格后，默认表示对该组 Demo 的核心页面样式满意。后续整套图片排版预览应尽量直接沿用被选中 Demo 的版式语言、色彩、质感和页面样式，不得无故重新生成另一个风格。

4. **主风格锁定**  
   用户选择主风格后，记录风格契约。若融合辅助风格，必须明确主次关系。  
   锁定风格时同步锁定被选中 Demo 的可复用页面样式，包括标题位置、视觉主轴、卡片质感、留白节奏、图文关系和品牌色使用方式。除非用户提出修改，否则不得在整套预览阶段推翻阶段 3 已确认的样式。

5. **整套图片排版预览**  
    用户确认主风格后，基于已选 Demo 样式生成全稿带真实文案的图片预览。可以提供多页合成一页的缩略图 / contact sheet 供快速浏览，但必须同时保存每个页面的单张高清图到独立过程文件夹，保证可追溯。
    这里的“排版预览图片”特指 Image 2 / imagegen 生成的带真实文案设计稿，用于确认图文融合、页面构图和视觉风格；不是最终 PPTX 映射可编辑文字后的导出截图。

6. **无字底图拆层**  
    用户确认带文案预览后，才生成或整理无字底图版，用于最终 PPTX 底层。无字底图 PNG 必须逐页保存到独立文件夹。

7. **可编辑 PPTX 制作**  
    用“无字视觉底图 + 原生可编辑文字/数字/标签”结构制作 PPTX，并复刻确认稿中的文字位置、层级、字号和对齐关系。
    推荐有效产出链路：确认无字底图通过 → 一次生成 PPTX → 轻量结构检查 → 必要时用 PowerPoint 后台导出 PNG 看总览 → 小修 → 最终导出。PowerPoint 导出 PNG 只是 QA 手段，不属于阶段 5 的正式排版预览交付物；如果导出失败或工具异常，最多尝试一次替代方案，不得反复排查拖慢交付。

## 禁止事项

- 未确认核心内容或附件，不得规划页数。
- 未确认阶段 3 的风格与关键页 Demo，不得生成整套图片预览或 PPTX。
- 未确认带文案整套图片预览，不得制作可编辑 PPTX。
- 不得用脚本拼接的低保真草图冒充 Image 2 高质量风格 Demo 或关键页 Demo。
- 不得只用文字说明让用户定风格。
- 不得把风格 Demo 图直接铺成每页背景；风格 Demo 只用于提取视觉语言，每页需按内容重新设计。
- 不得先生成无字底图再后期贴文案来替代设计稿确认。
- 若图文割裂，不得硬移文字适配底图，应优先重生成对应页面设计稿或底图。
- 如准备跳过任一阶段，必须先说明原因并请求用户确认。

每次回复开头必须声明当前阶段，例如：“阶段 3：风格偏好与关键页 Demo 可视化确认”。

## 图文一体设计要求

进入关键页 Demo 或整套图片预览前，必须先锁定真实文案，包括每页标题、正文、要点数量和文字长短。

Image 2 / imagegen 提示词必须明确：

- 页面真实标题和正文
- 要点数量
- 文字区域位置
- 文字密度
- 留白要求
- 角色/主视觉与文字的关系
- 禁止生成乱码、伪文字、无关文字或水印

关键页 Demo 和整套图片预览必须优先生成带真实文案版。  
只有在用户确认带文案设计稿后，才可拆出或重绘无字底图。

## 预览与验证边界

- 阶段 5 必须保存的是带真实文案的 Image 设计稿：逐页高清图 + 缩略总览，用于用户确认和过程追溯。
- 阶段 6 必须保存的是无字底图 PNG：逐页高清图，用于最终 PPTX 底层。
- 阶段 7 的 PPTX 导出截图只是质量检查，不是正式排版预览交付物。
- 阶段 7 必须做轻量结构检查：页数、底图数量、可编辑文本层、中文写入、关键替换词和文件是否存在。
- 只有在怀疑文字错位、遮挡、溢出，或用户明确要求视觉核对时，才导出 PPTX 渲染图 / PNG 总览检查。
- 如果本机 PowerPoint 可用，优先用 PowerPoint 后台导出做一次最终视觉 QA；若失败或耗时异常，改用结构检查并如实说明，不得反复尝试同一渲染链路。

## 分辨率与字号映射

当参考设计稿、截图、图片或 PDF 页面分辨率不固定，且需要拆成 PPT 页面时：

1. 必须记录参考图原始宽高和目标 PPT 页面宽高。
2. 建立归一化坐标：`x / y / w / h` 均按原始宽高比例换算。
3. 字号必须按原始图中文字高度、行距和页面比例推导。
4. 映射到 PPT 后，所有字号必须向上取整为整数 pt。
5. 不得为了塞文字而自动缩小字号；应优先改文案、改版式或重生成底图。
6. 同一文本角色，如标题、正文、标签、注释、页码，必须使用统一字号体系。

## 路径选择

| 输入与目标 | 路径 |
| --- | --- |
| 文案、文档或主题 → 新 PPT | A：图文一体设计到可编辑 PPT |
| 旧 PPT / 截图 / PNG / PDF → 高保真复刻 | B：视觉重建 |
| 旧 PPT 内容 + 新视觉重排 | C：内容重组 + 图文一体重设计 |

路径 A/C 必须先带文案设计，再拆无字底图。  
路径 B 可从参考图移除文字重建底图，但仍必须人工核对文字、位置、字号和图层。

## 路径 A/C：图文一体设计到成品

1. 提炼中心观点和每页“标题即结论”。
2. 删除无助于结论的内容，优先压缩文案，不靠缩小字号塞内容。
3. 先做带真实文案的关键页高质量 Demo，确认质感。
4. 再做带真实文案的整套图片预览，确认全稿节奏。
5. 用户确认后，生成或整理无字底图。
6. 用 `@oai/artifact-tool` JavaScript ES module 生成 PPTX，禁止使用 `python-pptx`。
7. 标题、正文、数字、标签、页码和页脚必须为原生可编辑文本。
8. 没有模板时，标题不少于 50pt（封面）、35pt（页面）、24pt（小标题）和 16pt（正文）；所有字号必须为整数 pt。
9. 过程文件必须可追溯：保存关键页 Demo、整套单页高清图、整套缩略图、无字底图和最终 PPTX。

## 路径 B：视觉重建

每页可见对象只允许两类：

- 底层：一张铺满页面、无任何文字或数字的完整 PNG 底图。
- 上层：所有文字、数字、标签、页码与图表标注对应的原生可编辑文本框。

执行要求：

1. 保存参考图并核对所有文字、数字、边界、样式和对齐。
2. 遮盖全部文字数字区域生成 mask。
3. 用生成式重绘 / inpainting 得到自然完整的无字底图。
4. 不得用白块、模糊块、纯色补丁覆盖文字。
5. 按语义文本块建立文本框，不得逐字逐行拆碎。
6. 从参考图建立归一化坐标，再映射到 PPT 页面。
7. 建立 manifest，记录底图、文本组、边界和图层声明。
8. 所有参考图、mask、无字底图、manifest 和最终 PPTX 必须保存到可追溯的交付/过程文件夹。

## 质量闸门

每完成一页都检查：

1. 标题是结论，且该页只传达一个主要信息。
2. 文本没有意外换行、截断、低对比或密度过高。
3. 图文关系自然，文字像设计的一部分，不像后期贴上去。
4. 没有非预期重叠、拉伸、失焦、重复主图或风格断裂。
5. 页码、页脚、标题层级和文字坐标在全稿中一致。
6. 数据、总量、比例、时间范围和结论相互一致。
7. 最终 PPTX 中，隐藏文字层后，底图必须无文字、无数字、无残影。
8. 移动任一文本框后，原位置不得露出旧字或补丁。

完整交付前，必须完成轻量结构检查。只有在怀疑错位、遮挡、溢出或用户要求视觉核对时，才渲染最终 PPTX 或生成最终截图总览；不得把最终 PPTX 截图总览替代阶段 5 的 Image 设计稿预览。

## 交付

始终交付可编辑 PPTX；新建或编辑内容时保留原文件，另导出新版本。

交付物和过程文件应至少包含：

```text
delivery/                                  # 最终交付与过程文件总目录
├── <topic>-editable.pptx                  # 最终可编辑 PPTX，文字/数字/标签应为原生可编辑层
├── backgrounds-no-text/                   # 无字底图目录，用于 PPTX 底层视觉
│   ├── slide-01-background.png            # 第 1 页无字底图，不应包含文字、数字、页码或 logo 文案
│   └── ...
├── preview-pages/                         # 带真实文案的 Image 设计稿单页预览目录
│   ├── slide-01-preview.png               # 第 1 页带文案设计稿，用于用户确认图文融合与版式
│   └── ...
├── preview-contact-sheet.png              # 多页缩略总览，用于快速查看整套预览节奏
├── source-or-reference/                   # 原始 PPT、参考图、品牌素材、IP 素材等来源文件
└── manifest.json                          # 拆层映射说明；路径 B 或复杂拆层时必需
```

最终说明只报告：

- 产物位置
- 页数
- 采用的风格 / 关键假设
- 已完成的验证
- 主要过程文件夹位置

不要把草稿计划、临时图、内部提示词或未确认预览当成正式交付。
