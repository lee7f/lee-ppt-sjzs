# 使用者档案

用于从项目资料提取使用者信息，并为封面、封底、个人简介页、署名和联系方式提供同一数据源。项目实际内容保存为项目根目录的 `02-使用者档案.md`。

## 信息分类

- 基础身份：姓名、职位、所属企业、所属部门、署名方式。
- 联系方式：邮箱、手机、微信、个人主页、企业官网、二维码。
- 视觉素材：个人照片、头像、个人 IP 形象。
- 页面规则：封面必显与可选、封底必显与可选、个人简介页必填与可选。
- 来源记录：来源文件、读取时间、本次新增字段、确认人。

## 问卷入口

- 不在首次调用时提醒维护使用者资料。
- 阶段 1 第 5 问选择需要个人简介页且没有档案时，读取 [个人信息问卷](presenter-questionnaire.md)。选择不需要时跳过问卷，无论是否首次使用都不得再询问是否填写。
- 已有档案时直接沿用，不询问是否更新；更新由用户主动发起。
- 问卷只询问资料和档案中缺失的必要项目。企业信息默认绑定内置品牌档案；没有内置企业档案时显示 `默认企业信息：未配置`。

## 使用规则

- 不得推测或生成邮箱、电话、微信、二维码及个人简介。
- 封面、封底只使用必显和可选列表中的字段；未列入的信息不得写入设计稿或 PPTX。
- 个人简介页必须具备个人简介、邮箱、个人 IP 或专业照片。手机、微信、所属企业和部门仅在原始资料或 PRD 提及时使用，未提及不追问。
- 个人照片、头像和个人 IP 仅按用户明确的页面范围使用。
- 技能包含 `assets/private-user/user-profile.yaml` 时，先验证档案和素材路径，再按同目录 `user-rules.md` 执行；值为 `pending`、`null` 或 `disabled` 的字段不得生成占位信息。
- 用户修改后立即更新项目档案，封面、封底、续作和 QA 读取同一版本。
- QA 检查实际页面与档案一致。

## 项目资料自动沉淀

- 无论是否需要个人简介页，只要项目资料明确包含个人信息，就无感新建或补充 `02-使用者档案.md`。
- 只补充空字段；一致信息不重复写入，冲突信息不覆盖。用户本轮明确要求优先于历史档案。
- 图片复制为稳定文件名，并记录来源文件、读取时间和本次新增字段。
- 资料没有明确页面位置时只保存备用，不扩大封面或封底使用范围；资料明确规定位置时同步记录。
- 自动处理不得打断资料分析。完成本轮读取后，若实际新增内容，说明新建或补充结果、实际新增字段和未覆盖冲突，并附档案链接；无新增时不提示更新。
